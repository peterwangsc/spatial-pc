# Consumer pairing v1

Goal: one physical display, LAN streaming and input. No cloud relay/account, certificate import, developer tools or lab keys for users. Existing SPC1/SPI1/textVersion1 stream stays unchanged. High-entropy setup fallback, not a PAKE or six-digit PIN design. No vetted PAKE implementation is already present on both platforms.

PC user enables access and opens Pair Device. Generate16CSPRNG bytes (128bits), display RFC4648 uppercase base32 without padding (26characters, grouped for readability; normalize ASCII spaces/hyphens/case only). Code never sent on wire or logged. Window expires180seconds, at most5 failed attempts, one pending pairing, explicit PC approval within60seconds. Valid proof consumes code/window; rejection/disconnect needs a fresh code. Pairing service exists only during this explicit window. Pairing endpoint TCP47990, TLS1.3 ALPN spatialpc-pair/1. Streaming TCP47991, TLS1.3 ALPN spatialpc/1. Production ports may conflict with lab until coordinated switch.

Discovery: Bonjour _spatialpc._tcp advertises stream port, txt version=1, pairPort=47990, pairing=0/1, hostId. Friendly name and discovery are UNTRUSTED until proof/pin succeeds. PC UI also shows LAN IPv4 for manual fallback. Never silently replace a stored host identity after a discovery/hostname/IP change. Restrict installer firewall rules to app/ports, Private profile and LocalSubnet. Public networks unsupported in MVP.

Pair wire: TLS payload records SPP1 + uint32BE JSON UTF8 length, 1..16384bytes, no compression, each message deadline5seconds except explicit approval up to60seconds. Only one handshake/session at a time; bounded backlog. First-run client permits the untrusted TLS leaf ONLY for pairing, never streaming, and captures its exact DER SHA256 from the actual TLS connection. It must not accept credentials or persist identity until proofs verify.

Server challenge fields: version1, type=challenge, hostId (32lowercasehex,16randombytes), windowId (base64,16randombytes), serverNonce(base64,32randombytes). Client creates a persistent P256 private key locally in Keychain; sends uncompressed ANSI X9.63 public point65bytes (not privatekey/PKCS12/CSR). ClientNonce32CSPRNG bytes. Client display name1..64UTF8bytes, no control characters, rendered as untrusted data. Standard base64 uses padding.

Exact transcript T is ASCII bytes SpatialPC-Pair-v1 followed by NUL, then actualTLSleafSHA25632bytes, hostId16bytes, windowId16bytes, serverNonce32bytes, clientNonce32bytes, publicPoint65bytes, uint16BE nameUTF8length, exact nameUTF8bytes. No JSON canonicalization. All fields have exact lengths; reject duplicate JSON keys and unknown message types.

Client proof fields: version1,type=proof,clientNonce,publicKey,name,proof,signature. proof=HMAC-SHA256(codeBytes, ASCII client followed byNUL || T). signature=ECDSA-P256-SHA256(ASCII client-key followed byNUL || T), ASN.1DER signature. Host constant-time verifies HMAC before accepting key/name/credential request, validates point/P256/signature proof of possession, and reserves the one window. Host sends pending message with serverProof=HMAC-SHA256(codeBytes, ASCII server followed byNUL || T). Client must constant-time verify this before waiting for local PC approval. Explicit local approval displays the authenticated request name; deny/time-out fails closed. Role labels prevent reflection; fresh window/nonces and actual TLS-leaf binding prevent replay and MITM credential substitution. Entropy prevents practical offline code guessing even if a malicious TLS endpoint gets a proof; this would be unsafe with short human PINs.

After approval only, server issues client X509 certificate for the provided key under its per-install local CA (clientAuth EKU, device ID in subject, <=365day validity) and atomically stores exact client-leaf fingerprint/deviceID/name as allowed. Paired response: version1,type=paired,hostId,deviceId,serverCertificate,clientCertificate,caCertificate (DER base64),serverName,streamPort47991. Same TLS connection is authenticated by completed certificate-bound mutual proofs. No client private key ever crosses network. Client validates returned certificate public key equals its own, hostId/leaf matches transcript/connection, clientAuth+chain/validity, and stores key+cert/serverpin atomically. If host committed but client failed, PC can revoke/re-pair; never relax verification. No credentials accepted on expired/canceled window.

Repeat streaming: existing mutualTLS with issuer/EKU/time checks AND exact server/client leaf pins. No anonymous fallback. Client stays bound to stored hostId/serverpin across DHCP/discovery. Windows private keys/config protected per user with DPAPI, restrictive ACL and atomic writes; AVP uses Keychain. Server leaf validity365days (plus five-minute clock-skew allowance), CA10years; rotation/reinstall identity change requires explicit re-pair for MVP. Expired client credentials require re-pair, no silent identity bypass.

Discovery advertises `_spatialpc._tcp.local.` while access is enabled. Only during the pairing window, `_spatialpc-pair._tcp.local.` advertises the separate pairing port with the same instance name/domain. Both carry version1 and hostId; neither establishes trust. Development ports are47993 for streaming and47992 for pairing. This separate service lets Apple's Network.framework resolve the pairing endpoint without changing a resolved stream endpoint's port.

Revoke device removes exact authorized leaf and immediately terminates its active stream/input with normal release cleanup. Disable access cancels pairing and all sessions/listeners. Only logged-in interactive user can enable access; default disabled, startup explicit opt-in. One concurrent stream, max10paireddevices, no unauthenticated capture. Code/proofs/keys/input content never enter diagnostics. Threat model excludes compromised endpoints or an attacker who sees the physical setup code; local approval remains required.

The Mac and Windows implementations use this accepted contract. Deterministic public test values are in pairing-v1-test-vector.json. Development uses separate identities and ports47992/47993; the existing lab identity is never imported. Code decoding rejects non-ASCII and noncanonical final padding bits; proof messages reject duplicate keys, nested values and unexpected fields. Approval expiry is rechecked immediately before state persistence.
